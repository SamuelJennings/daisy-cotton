{# @description A daisyUI dropdown: a trigger and a panel that opens beside it. By default the trigger is a button built from the dropdown's own extra attributes. #} {# @prop valign:select['top','bottom','left','right'] | default:"bottom" | description:"Side of the trigger the panel opens on." #} {# @prop halign:select['start','center','end'] | default:"start" | description:"Alignment of the panel along the trigger." #} {# @prop full:boolean | description:"Stretch the panel to the width of the trigger; otherwise it sizes to its content with a minimum width." #} {# @prop hover:boolean | description:"Open on hover instead of on click." #} {# @prop class:text | description:"Extra classes added to the dropdown wrapper." #} {# @prop content_class:text | description:"Extra classes added to the panel." #} {# @slot The panel content. #} {# @slot:button A custom trigger. When given, extra attributes fall through to the dropdown wrapper instead of a button, and the caller owns the trigger's tabindex and role. #} {% comment %} Trigger: by default, any extra attributes on the dropdown (text, icon, variant, size) are forwarded to an inner button that becomes the trigger. Positioning is done entirely in CSS by daisyUI's own dropdown classes. That is fine for a dropdown with room to open in its declared direction, and wrong wherever it does not have that room: a panel near the edge of the viewport or inside a scrolling ancestor can open off-screen or clipped. A project that needs smart placement (Floating UI or similar) layers it on top of this markup; it is not this package's concern. {% endcomment %} {% load daisy_cotton %}
